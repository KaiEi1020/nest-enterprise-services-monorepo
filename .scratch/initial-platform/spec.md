# 初始平台规格

Status: ready-for-agent

## Problem Statement

运营团队需要一个可在管理后台创建和管理的营销活动与奖品体系，学生能够在移动端浏览进行中的活动并用积分兑换奖品，兑换结果可被运营追踪并线下履约。当前仓库为空，需要同时建立承载该业务的企业级 NestJS BFF/BSC 架构基线，使后续功能可以在清晰的边界与可重复的工程流程上扩展。

## Solution

在企业级 NestJS Monorepo 中落地两条端到端链路：

- `admin-app` BFF 为管理后台提供管理员登录、用户管理、营销活动与奖品（含活动奖品配置）管理的 REST API。
- `student-app` BFF 为学生端提供登录、浏览进行中活动及其奖品、用积分兑换并查看兑换记录的 REST API。

两个 BFF 通过 gRPC 调用 `bsc-user`（身份、RBAC、积分余额）与 `bsc-marketing`（营销活动、奖品、兑换）两个核心领域服务；`bsc-marketing` 可同步 gRPC 调用 `bsc-user` 扣减或退还积分。领域动作在 BSC 内以 DDD 与 MikroORM 落地，跨服务异步通知使用 RocketMQ 领域事件。

## User Stories

1. 作为管理员，我想用账号密码登录管理后台，以便获得可执行管理操作的访问令牌。
2. 作为管理员，我想在令牌过期时使用刷新令牌换取新的访问令牌，以便不必频繁重新登录。
3. 作为管理员，我想创建用户，以便为学生与运营人员分配可登录身份。
4. 作为管理员，我想分页查询用户列表，以便查找与核对用户。
5. 作为管理员，我想查看单个用户详情，以便核对用户资料与状态。
6. 作为管理员，我想更新用户资料与状态，以便维护准确的用户信息。
7. 作为管理员，我想删除用户，以便停用不再使用的身份。
8. 作为管理员，我想创建奖品，以便在多个营销活动中复用同一权益或实物。
9. 作为管理员，我想为奖品设置全局固定兑换积分与全局可用库存，以便统一兑换价值与可用量来源。
10. 作为管理员，我想分页查询奖品列表，以便查找与核对奖品。
11. 作为管理员，我想查看单个奖品详情，以便核对其字段与可用库存。
12. 作为管理员，我想更新奖品，以便调整其名称、描述、图片、类型、兑换积分或可用库存。
13. 作为管理员，我想删除奖品，以便清理不再使用的奖品。
14. 作为管理员，我想创建营销活动，以便在确定时间范围内组织运营目标。
15. 作为管理员，我想为营销活动设置开始与结束时间，以便其状态在到达时间时自动流转。
16. 作为管理员，我想查询营销活动列表，以便核对当前与历史活动。
17. 作为管理员，我想查看单个营销活动详情，以便核对其配置与状态。
18. 作为管理员，我想更新营销活动，以便在发布前调整时间范围与配置。
19. 作为管理员，我想取消营销活动，以便停止不再需要的活动并释放其未发放库存。
20. 作为管理员，我想将一个奖品加入营销活动并分配活动库存，以便该活动可发放该奖品。
21. 作为管理员，我想调整某个活动奖品配置的活动库存，以便在活动期间增补或回收可发放量。
22. 作为管理员，我想从营销活动移除奖品配置，以便活动不再发放该奖品。
23. 作为管理员，我想分页查询待发放的兑换记录，以便安排线下发货或兑换。
24. 作为管理员，我想将待发放的兑换记录标记为已发放，以便记录履约完成。
25. 作为管理员，我想取消待发放的兑换记录，以便退还积分并释放活动库存。
26. 作为学生，我想用账号密码登录学生端，以便获得可兑换的访问令牌。
27. 作为学生，我想在令牌过期时使用刷新令牌换取新的访问令牌，以便保持登录。
28. 作为学生，我想分页浏览进行中的营销活动，以便选择参与活动。
29. 作为学生，我想查看某个进行中活动的详情及其奖品列表，以便选择要兑换的奖品。
30. 作为学生，我想用积分兑换活动中的奖品，以便获得该权益或实物。
31. 作为学生，我想在兑换时由系统校验积分余额与活动库存，以便在余额或库存不足时得到明确失败。
32. 作为学生，我想查询我的兑换记录，以便核对履约状态。
33. 作为运营系统，我想在营销活动到达开始时间时自动从已发布流转为进行中，以便学生端可见。
34. 作为运营系统，我想在营销活动到达结束时间时自动从进行中流转为已结束，以便停止兑换并释放未发放库存。
35. 作为运营系统，我想在兑换成功后扣减活动库存与用户积分，以便库存、积分与兑换记录保持一致。
36. 作为运营系统，我想在取消兑换时退还积分并释放活动库存，以便账务与库存可被追溯地纠正。
37. 作为运营系统，我想在活动库存调整时校验不得低于已发放数量，以便避免出现负库存。
38. 作为运营系统，我想在新增活动库存分配时校验全局可用库存，以便避免超额分配。
39. 作为运营系统，我想所有对外 API 使用 `/api/v1` 前缀与 OpenAPI 描述，以便客户端与契约可被稳定治理。
40. 作为运维人员，我想服务通过 gRPC 互相集成并通过 RocketMQ 发布领域事件，以便同步调用与异步通知边界清晰。

## Implementation Decisions

- 在 Nx 管理的 NestJS Monorepo 中创建应用与共享包：`apps/bff-admin`、`apps/bff-student`、`apps/bsc-user`、`apps/bsc-marketing`，以及 `packages/` 下的受限共享技术能力与协议契约。
- 每个应用遵循分层与目录约束：BFF 不引入 MikroORM 或业务数据库；每个 BSC 按领域模块组织为 `api/controller`、`api/dto`、`application/service`、`domain/entities`、`domain/repository`、`domain/vos`、`infrastructure/persistence/repositories`、`infrastructure/persistence/schemas`、`<domain>.module.ts`。
- 对外 REST API 使用 `/api/v1` 路径前缀，并通过 OpenAPI 暴露契约；gRPC Proto 作为 BFF 与 BSC 之间的同步契约，并保持向后兼容。
- 认证由 `bsc-user` 中的独立身份模块承载：使用非对称签名 JWT，签发短期 access token 与可轮换 refresh token；MSE Gateway 用公钥离线验签，剥离客户端身份头后注入受信用户上下文；BFF 执行用户级 RBAC。
- `bsc-user` 独占身份、用户、RBAC 与积分余额数据；`bsc-marketing` 独占营销活动、奖品、活动奖品配置、活动库存、兑换与兑换记录数据；两服务使用独立数据库或 Schema、迁移与数据库账号。
- `bsc-marketing` 可同步 gRPC 调用 `bsc-user` 的扣减积分与退还积分领域动作；`bsc-user` 不得反向依赖 `bsc-marketing`。
- 兑换为单一单位的同步流程：在 `bsc-marketing` 中预占活动库存、调用 `bsc-user` 扣减积分；扣减成功则确认库存扣减并生成待发放兑换记录，失败则释放预占库存并返回失败。
- 取消兑换由运营人员在 `bsc-marketing` 发起：标记兑换记录为已取消、释放活动库存，并调用 `bsc-user` 退还积分。
- 营销活动状态机为草稿、已发布、进行中、已结束、已取消；进行中与已结束由开始、结束时间自动流转，结束或取消时未发放活动库存释放回奖品可用量。
- 活动奖品配置可在活动发布后调整活动库存，但不得低于已发放数量；新增分配必须有奖品全局可用库存支撑。
- 跨服务异步通知使用 RocketMQ 领域事件，配合 Transactional Outbox、消费者幂等、重试与死信队列；首期可先定义事件契约并在落库时写出 outbox，消费端按需实现。
- 部署目标为阿里云 ACK：每服务独立镜像与 Helm Chart 推送到 ACR，环境以同集群独立 Namespace 隔离，滚动更新，并配置 startup、readiness、liveness 探针与回滚。
- 服务发现与动态配置使用 MSE Nacos；密钥通过 KMS 加密配置或 Secrets Manager 引用，禁止写入仓库与镜像。
- 观测性使用 OpenTelemetry、Prometheus 与以 Trace ID 关联的日志。

## Testing Decisions

- 测试只验证外部行为，不验证私有实现细节；优先复用既有接缝，避免新增跨代码库的接缝。
- BFF HTTP API 接缝：使用 supertest 启动 `bff-admin` 与 `bff-student` 的 Nest 实例，对 `/api/v1` 端点发起请求并断言响应状态与载荷；下层 BSC gRPC 客户端以 stub 替换，验证 BFF 的编排、视图组装与授权行为。
- BSC gRPC 接缝：对 `bsc-user` 与 `bsc-marketing` 的 gRPC handler 发起进程内调用，断言领域动作结果与状态流转；MikroORM 使用测试数据库或受控伪造，每个测试以独立事务回滚保证隔离。
- 状态机与库存不变量在 BSC 接缝层覆盖：活动状态自动流转、活动库存不得低于已发放、新增分配受全局可用库存约束、兑换扣减与取消退还的一致性。
- 由于当前仓库无既有测试可参照，本规格定义的接缝即为本期新建测试的先验范式。

## Out of Scope

- 学生端兑换数量大于一个单位的能力。
- 学生端自助取消兑换；取消仅由运营人员发起。
- 权益奖品的自动线上发放；首期所有奖品统一走线下发货或兑换，仅记录履约状态。
- 通用积分的获取与来源管理（签到、消费返积分等）；首期积分余额仅作为可兑换资源存在。
- 营销活动复杂规则引擎、定向人群、限人与限频等高级发放规则。
- 真正接入阿里云 ACK、ACR、MSE、RocketMQ、KMS 的生产部署；首期以本地与 CI 可运行代码为目标，部署基线作为约束记录在 ADR 中。
- Service Mesh 与 mTLS；首期以 NetworkPolicy、命名空间隔离与受信身份头约束网络与身份信任。
- 商品目录、订单、交易、库存等其他 BSC 领域。
